## 项目执行过程

### 1. 环境搭建阶段

1. **安装 Rust 工具链**
   - 下载并运行 `rustup-init.exe`
   - 选择默认安装选项
   - 验证安装：`rustc --version`、`cargo --version`
2. **安装 Visual Studio Build Tools**
   - 下载并运行 `vs_BuildTools.exe`
   - 选择「使用 C++ 的桌面开发」工作负载
   - 安装完成后验证：检查安装目录是否存在
3. **安装 Npcap**
   - 下载并运行 `npcap-1.80-installer.exe`
   - 选择「WinPcap API-compatible Mode」
   - 选择「Support raw 802.11 traffic」
4. **安装 MinGW-w64**
   - 解压 `mingw.7z` 到项目目录
   - 验证安装：`mingw64\bin\gcc.exe --version`

### 2. 项目配置阶段

1. **初始化 Rust 项目**
   - 创建项目目录结构
   - 配置 `Cargo.toml` 文件
   - 添加必要的依赖库
2. **配置网络接口**
   - 列出可用网络接口
   - 选择合适的网络接口用于监控
3. **配置环境变量**
   - 设置 API 端口
   - 设置认证令牌（可选）
   - 设置日志级别

### 3. 编译执行阶段

#### 3.1 编译后端服务

后端服务使用 **GNU 工具链**编译：

```powershell
# 切换到 GNU 工具链
rustup default stable-x86_64-pc-windows-gnu

# 设置 MinGW 路径
$env:PATH = "c:\my_projects\DKail\mingw64\bin;" + $env:PATH

# 编译后端
cd c:\my_projects\DKail

```

**为什么后端使用 GNU 工具链？**
- 后端项目依赖 Npcap 库，需要 MinGW 的导入库（`libwpcap.a`、`libPacket.a`）
- GNU 工具链对后端项目稳定可靠

#### 3.2 编译桌面应用（Tauri UI）

Tauri UI 编译过程较为复杂，经历了多次尝试才成功：

##### 尝试 1：GNU 工具链（失败）

```powershell
rustup default stable-x86_64-pc-windows-gnu
cd c:\my_projects\DKail\dkail-ui
npm run tauri dev
```

**错误**：
```
error: export ordinal too large: 104945
```

**原因**：Tauri 2.x 导出的符号数量超过了 GNU ld 链接器的限制（65535）。

##### 尝试 2：MSVC 工具链 Rust 1.95.0（失败）

```powershell
rustup default stable-x86_64-pc-windows-msvc
cd c:\my_projects\DKail\dkail-ui
npm run tauri dev
```

**错误**：
```
thread 'main' panicked at .../std/src/sys/process/mod.rs:65:17:
called `Result::unwrap()` on an `Err` value: Os { code: 0, kind: Uncategorized }
```

**原因**：Rust 1.95.0 在 Windows 上使用 MSVC 工具链时有已知的 panic bug。

##### 尝试 3：Rust 1.85.0（失败）

```powershell
rustup install 1.85.0
rustup default 1.85.0-x86_64-pc-windows-msvc
cd c:\my_projects\DKail\dkail-ui
npm run tauri dev
```

**错误**：
```
error: rustc 1.85.0 is not supported by the following packages:
  darling@0.23.0 requires rustc 1.88.0
  icu_collections@2.2.0 requires rustc 1.86
  ...
```

**原因**：Tauri 2.x 的依赖需要 Rust 1.86 或更高版本。

##### 最终解决方案：Nightly Rust + MSVC（成功）

```powershell
# 安装 nightly Rust
rustup install nightly

# 切换到 nightly MSVC 工具链
rustup default nightly-x86_64-pc-windows-msvc

# 验证版本
rustc --version
# 输出：rustc 1.97.0-nightly (66da6cae1 2026-04-20)

# 编译 Tauri UI
cd c:\my_projects\DKail\dkail-ui
npm install
npm run tauri dev
```

**成功原因**：
- Nightly Rust 修复了 MSVC 工具链的 bug
- MSVC 工具链没有符号数量限制
- 满足 Tauri 2.x 的依赖版本要求

##### 前端导入路径修复

编译过程中还发现前端代码有导入路径错误：

```typescript

// 正确的路径

```

- `src/pages/ProcessMonitor.tsx`
- `src/pages/ThreatDetection.tsx`
- `src/pages/Settings.tsx`
- `src/layouts/MainLayout.tsx`

## Npcap 工具集成

### 1. Npcap 简介

- **网络数据包捕获库**：基于 WinPcap 开发的 Windows 网络数据包捕获库
- **支持 WinPcap API**：兼容传统的 WinPcap 应用程序
- **支持 802.11 原始流量**：捕获无线网络原始帧
- **支持 Windows 10/11**：兼容最新的 Windows 版本

### 2. 安装与配置

#### 安装选项

- **WinPcap API-compatible Mode**：启用 WinPcap 兼容模式
- **Support raw 802.11 traffic**：支持原始 802.11 流量捕获
- **Install Npcap in WinPcap API-compatible Mode**：以 WinPcap 兼容模式安装

#### 安装路径

- **核心驱动**：`C:\Windows\System32\Npcap\`
- **动态链接库**：`C:\Windows\System32\wpcap.dll`、`C:\Windows\System32\Packet.dll`
- **开发文件**：`C:\Program Files\Npcap\`

### 3. 在项目中使用 Npcap

#### Rust 依赖

```toml
# Cargo.toml
[dependencies]
pcap = "0.8.0"
```

#### 基本使用

```rust
use pcap::Device;

// 列出可用网络接口
let devices = Device::list().unwrap();
for device in devices {
    println!("{:?}", device);
}

// 打开网络接口进行捕获
let device = Device::list()?.into_iter().find(|d| d.name == interface_name).ok_or("Interface not found")?;
let mut cap = Capture::from_device(device)?
    .promisc(true)
    .snaplen(65535)
    .open()?;

// 捕获数据包
loop {
    match cap.next_packet() {
        Ok(packet) => {
            // 处理数据包
        }
        Err(e) => {
            warn!("Packet capture error: {}", e);
        }
    }
}
```

### 4. 解决 Npcap 链接问题

#### 问题描述

- MinGW 无法找到 wpcap 库
- 编译时出现链接错误

#### 解决方案

1. **生成导入库**
   ```powershell
   # 使用 gendef 生成 .def 文件
   gendef "C:\Windows\System32\wpcap.dll"
   gendef "C:\Windows\System32\Packet.dll"

   # 使用 dlltool 生成 .a 文件
   dlltool -d wpcap.def -l libwpcap.a
   dlltool -d Packet.def -l libPacket.a
   ```
2. **配置链接器**
   ```toml
   # Cargo.toml
   [build-dependencies]
   pkg-config = "0.3"

   [dependencies]
   pcap = { version = "0.8.0", features = ["packetdump"] }
   ```
3. **wpcap\_lib 目录说明**

   生成的库文件应该存放在 `wpcap_lib` 目录中，该目录包含以下文件：
   | 文件            | 描述                   |
   | ------------- | -------------------- |
   | `wpcap.dll`   | WinPcap 兼容的网络数据包捕获库  |
   | `Packet.dll`  | 底层网络数据包捕获库           |
   | `wpcap.def`   | wpcap.dll 的导出函数定义文件  |
   | `Packet.def`  | Packet.dll 的导出函数定义文件 |
   | `libwpcap.a`  | MinGW 编译器使用的静态导入库    |
   | `libPacket.a` | MinGW 编译器使用的静态导入库    |
   **用途**：
   - 这些文件是网络监控模块的核心依赖，用于捕获和分析网络数据包
   - `libwpcap.a` 和 `libPacket.a` 是为 MinGW 工具链生成的导入库，解决了 Rust 项目在 Windows 上链接 Npcap 库的问题
   - 当编译项目时，链接器会使用这些库文件来解析网络数据包捕获相关的函数调用

### 2. 网络监控模块

#### 使用 Npcap

- **捕获数据包**：使用 `pcap` 库调用 Npcap API
- **解析数据包**：解析以太网帧、IP 头部、TCP/UDP 头部

#### 实现代码

```rust
use pcap::Device;

pub async fn start_capture(&mut self, state: Arc<RwLock<SystemState>>) -> Result<(), Box<dyn std::error::Error>> {
    let device = Device::list()?
        .into_iter()
        .find(|d| d.name == self.interface_name)
        .ok_or("Interface not found")?;
    
    let mut cap = Capture::from_device(device)?
        .promisc(true)
        .snaplen(65535)
        .open()?;
    
    loop {
        match cap.next_packet() {
            Ok(packet) => {
                self.process_packet(packet.data);
            }
            Err(e) => {
                warn!("Packet capture error: {}", e);
            }
        }
    }
}
```

### 3. 进程监控模块

#### 使用 Windows API

- **枚举进程**：使用 `EnumProcesses` API
- **获取进程信息**：使用 `OpenProcess` 和 `QueryFullProcessImageNameW` API
- **管理进程句柄**：使用 RAII 模式确保句柄正确关闭

#### 实现代码

```rust
use winapi::um::psapi::EnumProcesses;
use winapi::um::processthreadsapi::OpenProcess;
use winapi::um::winnt::PROCESS_QUERY_LIMITED_INFORMATION;

fn enumerate_processes(&mut self) -> Result<(), Box<dyn std::error::Error>> {
    let mut process_ids: [u32; 1024] = [0; 1024];
    let mut bytes_returned: u32 = 0;
    
    unsafe {
        if EnumProcesses(
            process_ids.as_mut_ptr(),
            (1024 * size_of::<u32>()) as u32,
            &mut bytes_returned
        ) == 0 {
            return Err("EnumProcesses failed".into());
        }
    }
    
    let process_count = (bytes_returned as usize / size_of::<u32>()).min(1024);
    
    for i in 0..process_count {
        let pid = process_ids[i];
        if pid == 0 {
            continue;
        }
        
        if let Ok(info) = self.get_process_info(pid) {
            self.process_cache.insert(pid, info);
        }
    }
    
    Ok(())
}
```

### 4. API 服务器

#### 使用 Actix-web

- **创建 HTTP 服务器**：使用 `HttpServer` 组件
- **定义路由**：配置 API 端点
- **处理请求**：实现请求处理函数
- **状态管理**：使用 `Arc<RwLock<SystemState>>` 共享状态

#### 实现代码

```rust
use actix_web::{web, App, HttpServer, HttpResponse, Responder};

pub async fn start(&self, state: Arc<RwLock<SystemState>>) -> std::io::Result<()> {
    let state_data = web::Data::new(state);
    
    HttpServer::new(move || {
        App::new()
            .app_data(state_data.clone())
            .route("/", web::get().to(index))
            .route("/status", web::get().to(status))
            .route("/alerts", web::get().to(alerts))
            .route("/processes", web::get().to(processes))
            .route("/network", web::get().to(network))
    })
    .bind(("127.0.0.1", self.port))?
    .run()
    .await
}
```

#### 1.3 网络监控自动检测接口

**问题描述**：

**解决方案**：
修改 `start_monitoring_with_shutdown` 函数，自动检测并使用第一个可用的网络接口：

```rust
pub async fn start_monitoring_with_shutdown(
    state: Arc<RwLock<SystemState>>,
    shutdown_flag: Arc<tokio::sync::watch::Receiver<bool>>,
) -> Result<(), NetworkError> {
    let interface = std::env::var("DKAIL_NETWORK_INTERFACE")
        .unwrap_or_else(|_| {
            if let Ok(devices) = pcap::Device::list() {
                for device in &devices {
                    if !device.name.contains("Loopback") && !device.name.is_empty() {
                        if let Some(desc) = &device.desc {
                            if desc.contains("Ethernet") || desc.contains("Wi-Fi") || desc.contains("Wireless") {
                                info!("Auto-detected network interface: {} ({})", device.name, desc);
                                return device.name.clone();
                            }
                        }
                    }
                }
                // Fallback to first non-loopback interface
                for device in &devices {
                    if !device.name.contains("Loopback") && !device.name.is_empty() {
                        return device.name.clone();
                    }
                }
            }
            "\\Device\\NPF_Loopback".to_string()
        });
    
    let mut monitor = NetworkMonitor::with_shutdown(interface, shutdown_flag);
    monitor.start_capture(state).await
}
```

### 5. 安全漏洞修复（2026-04-22）

代码审查专家发现了 10 个安全漏洞，已全部修复：

#### 5.1 严重漏洞（1个）

**API 认证完全无效**

**问题描述**：
API 端点只检查了 token 是否配置，但没有实际验证请求头中的 Bearer 令牌。

**解决方案**：
实现 `verify_auth()` 函数，使用 `constant_time_eq` 安全比较 Bearer 令牌：

```rust
fn verify_auth(req: &HttpRequest, expected_token: &Option<String>) -> Result<(), ErrorResponse> {
    if let Some(token) = expected_token {
        let provided_token = extract_bearer_token(req)
            .ok_or_else(|| ErrorResponse {
                error: "Missing or invalid Authorization header".to_string(),
                code: 401,
            })?;
        
        if !constant_time_eq(&provided_token, token) {
            warn!("Authentication failed: invalid token");
            return Err(ErrorResponse {
                error: "Invalid authentication token".to_string(),
                code: 401,
            });
        }
    }
    Ok(())
}

fn constant_time_eq(a: &str, b: &str) -> bool {
    if a.len() != b.len() {
        return false;
    }
    let mut result = 0u8;
    for (x, y) in a.bytes().zip(b.bytes()) {
        result |= x ^ y;
    }
    result == 0
}
```

fn sanitize_path(path: &str) -> String {
    if path.is_empty() {
        return path.to_string();
    }
    
    path.replace(|c: char| c == '\\' || c == '/', "/")
        .split('/')
        .map(|part| {
            if part.len() > 2 && part != "Users" && part != "Program Files" {
                if part.chars().all(|c| c.is_alphanumeric() || c == '_' || c == '-' || c == '.') {
                    if !part.contains('.') && part.len() < 20 {
                        return "***";
                    }
                }
            }
            part
        })
        .collect::<Vec<_>>()
        .join("/")
}

**1. 缺乏速率限制**

添加 `RateLimiter` 类，限制每 IP 每 60 秒最多 100 次请求：

```rust
pub struct RateLimiter {
    requests: Arc<RwLock<HashMap<String, Vec<Instant>>>>,
    max_requests: usize,
    window_secs: u64,
}

impl RateLimiter {
    pub async fn check(&self, client_ip: &str) -> bool {
        let mut requests = self.requests.write().await;
        let now = Instant::now();
        let window = Duration::from_secs(self.window_secs);
        
        let entry = requests.entry(client_ip.to_string()).or_insert_with(Vec::new);
        entry.retain(|&t| now.duration_since(t) < window);
        
        if entry.len() >= self.max_requests {
            return false;
        }
        entry.push(now);
        true
    }
}
```
